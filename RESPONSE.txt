REVIEWER 1

Comment 1. Zero false answers depend on truthful and complete metadata; this is a fundamental limitation.

Response. We agree and have made this limitation explicit in the abstract, Introduction, gate description, property table, Discussion, and Conclusion. The identification gate checks a finite library of sufficient declared conditions; it does not establish whether those declarations are true. Incorrect randomization claims, omitted confounders, and an incorrect exposure mapping can pass the implemented rules. Observationally equivalent causal models can imply different intervention effects, so this limitation cannot be removed by checking the observed table alone.

The stress result is now described as contract compliance, not a zero rate of incorrect causal estimates. We also clarified the confirmatory property test: 1,200 distinct gate evaluations are recorded under 13 method labels. The 15,600 recorded statuses are not 15,600 independent tests or numerical evaluations of all estimators on invalid queries. Its ungated answer indicator is true by definition.

The public result view now states the conditional meaning of an accepted causal answer. Network analysis requires an explicit no-unmeasured-confounding declaration instead of automatically asserting it. A regression test demonstrates that changing an ignorability declaration changes the decision without establishing the truth of the declaration.

Locations: Abstract; Sections 1, 4.5, 4.8, 6.1, 6.4, 7.1, and 8; Table 3. Implementation: cwfm/application/contracts.py, decision_policy.py, app/pages/analyze.py, app/components/result_status.py, and tests/test_support_revision.py.

Comment 2. The shallow selector and convex stack outperform the deep router; this finding should lead the paper.

Response. We reframed the paper around the integrated assumption, support, estimation, and calibration interface. The deep router is explicitly an evaluated baseline. The abstract, Introduction, first Results subsection, Discussion, and Conclusion now report the confirmatory pooled MAEs: 0.141 for the shallow random-forest risk selector, 0.147 for the convex stack, and 0.161 for the frozen router, on 1,800 queries. Table 5 reports paired confidence intervals and coverage. We distinguish the shallow risk selector from random-forest g-computation, which is a different outcome estimator.

The confirmatory comparison now opens the Results section instead of appearing as an ancillary follow-up. We retain the existing public checkpoint for reproducibility. Replacing it with a shallow selector would require packaging that fitted policy and matching calibration, which is outside this focused revision. No claim of a deep-routing accuracy advantage remains.

Locations: Abstract; Sections 1, 6.1, 7.1, and 8; Table 5; release MODEL_CARD.md.

Comment 3. Benchmark the finite-sample empirical support statistic used by the application.

Response. We added a direct audit of the actual public screening functions, including the minimum treatment-group count condition. It uses sample sizes 32, 64, 128, 256, and 512; two static assignment families with six severities each; and a degree-four network with four assignment probabilities. Every cell has 500 independent dataset replicates. There is no effect fitting, neural inference, retraining, or threshold tuning.

The reference is the existing practical-overlap policy applied to a known population distribution. It is not strict mathematical positivity or causal correctness. We define false refusal as rejection in a population-adequate cell and false acceptance as acceptance in a population-inadequate cell. If a positive decision means detecting inadequate support, the false-positive rate is the false-refusal rate. Both error directions are reported, with pointwise 95% Wilson intervals.

For linear assignment at slope one, false refusals decrease from 0.528 at n=32 to 0.106 at n=128 and zero at n=512. For quadratic assignment at slope two, all 500 datasets are accepted at both n=128 and n=512 despite failing the population reference. Increasing sample size does not repair a misspecified linear-probability screen. In the network setting at assignment probability 0.3, false refusal remains 0.246 at n=512. These results explicitly limit practical deployment claims.

The audit also motivated two small correctness repairs: a passing exposure check can no longer overwrite an earlier treatment-group support failure, and a missing own-treatment group cannot pass the exposure function. The numerical thresholds are unchanged. The audit evaluates this corrected composition, and regression tests cover both defects.

Locations: Sections 4.5, 5.7, 6.8, 7.1, and 7.2; Figure 12; Table 10. Reproduction: experiments/support_protocol.json, cwfm/support_experiment.py, and artifacts/cwfm/support_revision/. The artifacts include all per-replicate decisions, all 80 summaries, intervals, code and data hashes, and environment information.

Comment 4. Describe the encoder as presentation-randomized, not position-blind, and discuss index sensitivity.

Response. We corrected the description. The cell encoder has no separate column-position embedding, but the query vector contains normalized treatment, outcome, and exposure indices. Training and the confirmatory column-permutation probes permute columns within role groups; they do not establish invariance to arbitrary relocation of query-role columns. Named public adapters arrange the query columns, but adding covariates can still change their indices.

We retain the original single-episode changes of 0.170 after covariate reordering and 0.039 after irrelevant-covariate insertion. We explain the classical estimator-layer repairs that preceded the existing confirmatory experiment and avoid attributing those repairs to architectural invariance. The 97.25% confirmatory pass rate is now explicitly restricted to row permutation, within-role covariate permutation, outcome translation, and positive scaling. Negative outcome scaling and treatment-label recoding retain unresolved equivariance errors.

Removing the index inputs would change the checkpoint interface and require retraining. The less invasive revision is to describe and delimit the current architecture accurately.

Locations: Sections 4.3, 5.1, 6.1, 6.7, and 7.2; Table 9; release MODEL_CARD.md.
